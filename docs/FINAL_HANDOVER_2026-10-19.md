## 2. الرؤية ونطاق المنتج المعتمد

- الصفحة الرئيسية تجربة **متصفح Chromium حقيقي** وتبويباته، وبجانبه صندوق تعليمات للمساعد.
- فتح أي عنوان HTTP/HTTPS يدويًا مسموح من المتصفح المحلي. تنفيذ المساعد الآلي مقيد بمواقع HTTPS عامة مصرح بها داخل **نفس التبويب والنطاق الأصلي** المختار.
- يستطيع الوكيل تنفيذ سلسلة محدودة **بحد أقصى أربع خطوات آمنة**، لا إنجاز مهمة مفتوحة بلا حد أو عملًا مستقلًا عبر مواقع وحسابات متعددة.
- ظهور المهام أو الحسابات في معاينة Lovable لا يعني أنها اتصلت بجهاز المستخدم؛ المعاينة المستضافة منفصلة عن الخدمات المحلية ولا يجوز إدخال رموزها أو أسرارها هناك.
- لا يُسمح بادعاء نجاح إرسال أو نشر لم يظهر في سجل عمليات متحقق منها.

## 3. المكونات المنفذة

### أ) واجهة المستخدم

- React/TanStack، واجهة عربية RTL وتنسيق متجاوب، متصفح في الشاشة الرئيسية.
- تبويبات وتصفح يدوي وعرض Chromium عبر noVNC، وصندوق مهام وتعليمات في نفس الصفحة.
- واجهات المحادثة والذاكرة وأساليب الرد والتقارير والموافقات وصلاحيات المواقع والإعدادات وتشخيص جاهزية الخدمات.
- تقارير ببحث وتصفية، روابط مركزة للمهام، وموافقات قابلة للمراجعة؛ وضع المعاينة التجريبي واضح ولا يدّعي تنفيذًا حقيقيًا.
- منع إرسال رموز الخادم المحلي من واجهة مستضافة خارج `localhost` و`127.0.0.1` بنطاقات الوصول المقصودة.

### ب) المحرك المحلي وقاعدة البيانات

- Fastify مع Bearer Token وCORS محصور في أصول محلية، وسجلات أحداث وتفويض/حالات تحكم `MANUAL` و`AGENT_ACTIVE` و`PAUSED` و`STOPPED` وغيرها.
- سبع ترحيلات SQL مُطبّقة ومختبرة على PostgreSQL 16 حقيقي داخل CI:
  1. `001_control_and_audit.sql` — حالة التحكم والتدقيق.
  2. `002_chat.sql` — المحادثات.
  3. `003_knowledge.sql` — الذاكرة والنسخ السابقة.
  4. `004_agent_tasks.sql` — المهام وسجل خطواتها ونتائجها.
  5. `005_notifications.sql` — تنبيهات داخلية مقتضبة.
  6. `006_approval_queue.sql` — مسودات الموافقات المقيّدة.
  7. `007_review_permissions.sql` — صلاحيات مراجعة المواقع، افتراضيًا معطلة.
- عند إعادة التشغيل لا تُستأنف مهام قديمة خطرًا بشكل تلقائي؛ يُطبّق منطق استعادة حالة آمنة.

### ج) Ollama والذاكرة

- اكتشاف النماذج المحلية، بث الردود، إلغاء التوليد، وحفظ المحادثة في PostgreSQL.
- استرجاع سياق محدود من التعليمات وأساليب الرد المسجلة محليًا.
- اجتاز بروتوكول Ollama اختبارات وحدات وتكامل عبر خادم HTTP تجريبي. **لم يُجرَّب استدلال Ollama الحقيقي على كمبيوتر المالك**.

### د) Chromium وPlaywright

- حاوية Chromium مرئية عبر Xvfb + x11vnc/noVNC، منافذ محلية، رمز خدمة منفصل وكلمة مرور VNC منفصلة، مع ملف تعريف مخزّن في Docker Volume.
- إنشاء/تفعيل/إغلاق تبويبات، وفتح مواقع يدويًا وحفظ الجلسة عبر إعادة تشغيل الحاوية.
- اختبارات CI تضمنت استعادة كوكي اصطناعية بعد إعادة تشغيل الحاوية، والتحقق من العودة إلى وضع الإيقاف/read-only.
- عامل AI لا يقبل CSS/JavaScript/XPath حرًا، ولا نقرًا عامًا أو تقديم نموذج؛ فقط عمليات محدودة متحقق منها: **قراءة الصفحة، تمرير، انتقال HTTPS مصرح به في النطاق نفسه، اتباع رابط آمن، وملء حقل نصي غير حساس دون ضغط إرسال**.
- **قيد مهم:** الكتابة في حقول بعض المواقع قد تؤدي إلى حفظ تلقائي حتى دون زر إرسال؛ لا تستخدمها لمعلومات حساسة.
- اختبار GitHub للمتصفح يستخدم وضعًا مؤقتًا **دون وصول خارجي** مع استثناء لعزل Chromium الداخلي بسبب قيود AppArmor في runner. **التشغيل على الجهاز الحقيقي يحافظ على Chromium sandbox مفعّلًا**؛ لا يُسمح بإلغائه لتصفح حسابات فعلية.

### هـ) الموافقات والصلاحيات والإشعارات

- موافقات لمسودات ذات بصمة SHA-256، مع انتهاء صلاحية وقرارات نهائية ومراجعة بشرية. **الموافقة لا تنفذ إرسالًا أو نشرًا**.
- صلاحيات المواقع افتراضيًا `can_review=false`، وحق الكتابة الخارجية معطل في قاعدة البيانات. العامل يتحقق من إذن النطاق والقيود قبل المتابعة.
- إشعارات داخلية عند اكتمال/فشل/إلغاء المهمة دون نسخ محتوى الصفحة إلى الإشعار.
- **غير موجود:** منفذ رسمي لإرسال WhatsApp/Email أو نشر Facebook/Instagram، تنفيذ المدفوعات/الحذف، أو ضغط أي زر دون سياسة وفحص إضافيين.

### و) Windows والتشخيص والنسخ الاحتياطي

- ملفات PowerShell لإعداد الخدمات وفحص التكوين وتشغيلها وتشخيصها دون طباعة الأسرار.
- فحص `preflight.ps1` يتحقق من رموز الخدمات وبيانات PostgreSQL وأصول الاتصال المحلية ويرفض وضع CI غير الآمن على الكمبيوتر الشخصي.
- النسخ الاحتياطي PostgreSQL بتشفير AES-256-GCM وscrypt إلى `.pawbak`، وفحص سلامة واستعادة إلى **قاعدة جديدة غير مدمرة**.
- نسخ يومي اختياري مجدول عبر Windows Task Scheduler مع حماية عبارة المرور باستخدام DPAPI لحساب Windows نفسه؛ غير مفعّل افتراضيًا، ولا يوجد حذف تلقائي للنسخ القديمة.
- نسخ جلسة Chromium بأرشيف `.pawprofile` مستقل ومشفر **بعد إيقاف المتصفح**، مع الاستعادة إلى Volume جديد غير متصل، دون استبدال الجلسة الأصلية أو ضمان نقل تسجيلات الدخول بين أجهزة مختلفة.

## 5. عناصر غير منتهية / معايير عدم الجاهزية الإنتاجية

**P0 — يجب إكمالها قبل استخدام بيانات أو حسابات حقيقية:**

1. تشغيل النظام على Windows الفعلي والتحقق من إعداد Docker Desktop/WSL2، مع تشغيل Chromium sandbox دون استثناءات الاختبار.
2. تشغيل نموذج Ollama حقيقي محليًا وتأكيد الاستدلال وحالات انقطاع الخدمة.
3. تجربة تبديل تبويبات Chromium يدويًا، إدخال noVNC، الاستعادة بعد إعادة التشغيل، وقفل/إرجاع الملكية في حالات الإيقاف والإلغاء.
4. تنفيذ مهمة آمنة على موقع تجريبي/مصرح به في التبويب المحدد، والتحقق من سجل الخطوات وعدم ادعاء أفعال غير منفذة؛ بدون تسجيل دخول حسابات حقيقية أولًا.
5. تجربة استعادة PostgreSQL من ملف مشفر ونسخ ملف Chromium منفصلًا على Windows والتحقق من عدم المساس بالبيانات الأصلية.
6. تدقيق صلاحيات المستخدم والخصوصية والأسرار والموارد/الأداء الفعلي على الجهاز.

**P1 — استكمال الجودة والتشغيل اليومي:** تجربة واجهة المستخدم محليًا على شاشات مختلفة، التأكد من فحص الجاهزية وسيناريوهات فشل الشبكة، وتفعيل وجدولة النسخ اليومية بصورة اختيارية بعد اختبار الاستعادة ومراجعة مساحة التخزين.

**P2 — مزايا مستقبلية خارج قبول هذه النسخة:** تكاملات رسمية مصرح بها لرسائل أو منشورات، موافقة صريحة لكل فعل خارجي وتدقيق لاحق، تنبيهات Telegram باشتراك اختياري، مهام دورية ووكيل متعدد الخطوات/المواقع بعد تصميم حدود الوصول.

## 6. تشغيل Windows — للمستخدم عند بدء الاختبار المحلي

**المتطلبات:** Windows مع Docker Desktop/WSL2، Node.js 22+، Bun، Ollama، PowerShell؛ تحميل نموذج محلي مناسب للمواصفات (مثال `ollama pull llama3.2`).

من **جذر المستودع** وبعد تثبيت المتطلبات وتشغيل Docker وOllama:

```powershell
.\scripts\windows\launch.ps1
```

أول تشغيل يجهز ملفات الأسرار الخاصة محليًا دون استبدال إعدادات موجودة. ثم الوصول إلى `http://127.0.0.1:8080`، وإدخال `RUNTIME_TOKEN` من `runtime/.env` **داخل الواجهة المحلية فقط**. لا تُرسل ملف `.env` أو أي رموز في الدردشة أو GitHub أو Lovable.

للتشخيص بعد التشغيل:

```powershell
.\scripts\windows\diagnose.ps1 -Strict -TestInference
```

**ملحوظة:** لا تختَر تجاوز Sandbox عند فشل Chromium، ولا تنفذ `docker compose down -v` على بياناتك الحقيقية لأنه قد يحذف Volumes.

الأدلة: [Windows](WINDOWS_QUICKSTART.md) · [حالة الوظائف](CURRENT_STATUS.md) · [نسخ PostgreSQL](BACKUP_AND_RESTORE.md) · [نسخ Chromium](CHROMIUM_PROFILE_BACKUPS.md).

## 7. الأمن والخصوصية والنشر

- المستودع **عام**؛ لا تُضف إليه صور هويات أو مفاتيح أو كلمات مرور أو ملفات `.env` أو كوكيز أو نسخ احتياطية خاصة.
- لا تحوّل واجهة Lovable المستضافة إلى قناة للأسرار أو إلى وكيل متصل بخدمات جهازك.
- جميع منافذ الخدمات المحلية يجب أن تظل loopback، ويُفضّل تفعيل BitLocker/تشفير القرص لحماية الملفات وقواعد البيانات والـDocker Volumes.
- لا تستخدم حسابات حقيقية قبل اجتياز الاختبار المحلي على Sandbox مفعّل وبدون أي صلاحيات نشر.
- لا تعدّل سجل Git باستخدام Force Push أو Rebase لمسح التاريخ؛ التزامن الحالي سليم.
