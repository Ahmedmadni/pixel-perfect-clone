# النسخ الاحتياطي المشفّر والاستعادة الآمنة — Personal AI Workspace

هذه المرحلة تحفظ **PostgreSQL فقط**: الذاكرة وأساليب الردود
والمحادثات والموافقات والصلاحيات وسجل المهام والتنبيهات والتدقيق.
لا يشمل الأرشيف رموز الدخول أو كلمات المرور المخزنة في ملفات `.env`،
ولا كوكيز Chromium أو متصفح Docker ولا نماذج Ollama.

## النسخ الاحتياطي على Windows

بعد تشغيل Docker وPostgreSQL محليًا، افتح PowerShell من جذر المستودع:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\backup.ps1
```

سيطلب السكربت كلمة مرور **لا تقل عن 16 حرفًا**، مع تأكيدها دون عرضها على
الشاشة. يحفظ نسخة محمولة بامتداد `.pawbak` في
`%USERPROFILE%\PAW-Backups`. ويمكن اختيار موقع آخر:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\backup.ps1 -OutputPath "D:\PrivateBackups\my-workspace.pawbak"
```

الملف مشفر بتقنية AES-256-GCM وبمفتاح مشتق باستخدام scrypt، مع ملح
ومعامل IV عشوائيين وفحص سلامة يعتمد على وسم المصادقة. لا يتم الاحتفاظ
بنسخة من كلمة المرور على GitHub أو داخل قاعدة البيانات. **احتفظ بكلمة
المرور في مدير كلمات مرور موثوق؛ فقدانها يعني تعذر فك النسخة.**

لا يسمح البرنامج بحفظ النسخة داخل مستودع GitHub أو استبدال ملف
`.pawbak` موجود بالفعل، وتُحذف الملفات الجزئية إذا فشلت العملية.

## اختبار الاستعادة دون المساس ببياناتك

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\restore.ps1 -InputPath "D:\PrivateBackups\my-workspace.pawbak"
```

بعد إدخال كلمة المرور، يتحقق البرنامج أولًا من سلامة البيانات المشفرة،
ثم ينشئ قاعدة **جديدة** باسم يبدأ بـ`paw_restore_` ويسترجع الجداول
فيها. لن يستبدل قاعدة `paw` الحالية؛ والاستعادة الفاشلة تحذف قاعدة
التجربة التي أنشأتها العملية فقط. تبقى القاعدة المستعادة في Docker Volume
للفحص والمقارنة، ولا تُفتح تلقائيًا في التطبيق.

## حدود الأمان

- الملفات المخزنة في PostgreSQL على جهازك **ليست مشفرة بالضرورة**؛
  استخدم تشفير القرص الكامل في Windows.
- أثناء الاستعادة يتكون ملف PostgreSQL غير مشفر **مؤقتًا** في مجلد خاص
  بالمستخدم، بعد التحقق من كلمة المرور وقبل أمر `pg_restore`، ثم يحذفه
  البرنامج عند انتهاء العملية. الحذف لا يضمن محو البيانات على SSD؛
  استخدم تشفير القرص ولا تنفذ استعادة على كمبيوتر مشترك.
- لا تُرسل النسخة المشفرة أو كلمة مرورها إلى المحادثة أو Lovable أو
  GitHub؛ النسخ إلى Google Drive يتم بواسطة المستخدم بعد إنشاء
  النسخة، ورفعها إلى السحابة **ليس تلقائيًا**.
- يمكن أن تحتوي قاعدة البيانات على بيانات شخصية، لذا لا تترك
  نسخًا قديمة بدون إدارة. لا يوجد حتى الآن جدول نسخ تلقائية ولا
  نسخ مشفرة لملف متصفح Chromium.
- استعادة البيانات إلى قاعدة قديمة أو دمج النسخة مع بيانات قائمة
  غير مدعوم عمدًا؛ يجب اعتماد مسار آمن منفصل قبل إتاحة ذلك.
- نسخة PostgreSQL بصيغة custom من الإصدار 16؛ يفضل الاستعادة بنفس
  الإصدار أو إصدار أحدث متوافق، مع اختبار الترحيلات في البيئة المستهدفة.
- كلمات المرور القوية مطلوب أن تتكون من 16 حرفًا على الأقل. اختر
  عبارة فريدة طويلة ولا تستخدم أسرار حساباتك الخارجية.

## الاختبار

تشغّل GitHub Actions اختبارات ملف التشفير ونسخة واستعادة قاعدة
PostgreSQL **تجريبية** ذات بيانات غير حقيقية، بما فيها رفض كلمة مرور
خاطئة والتأكد من عدم تغيير القاعدة الأصلية.

`node --test scripts/backup/crypto.test.mjs` يفحص طبقة التشفير فقط.

نجاح CI لا يعني نجاح التشغيل على Windows الخاص بك حتى تُجرّب النسخ
والاستعادة فعليًا من خلال `backup.ps1` و`restore.ps1`.
