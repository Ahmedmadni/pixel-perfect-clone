# المتصفح الذكي — ما الذي يعمل وما الذي لا يعمل؟

**تحديث: 19 أكتوبر 2026** · المستودع: `Ahmedmadni/pixel-perfect-clone`، الفرع `main`.

## الفكرة النهائية

واجهة واحدة: متصفح Chromium وتبويبات حقيقية، وبجانبه صندوق تعليمات
للمساعد. المستخدم يفتح أي عنوان HTTP/HTTPS يدويًا ويختار التاب بنفسه.
المساعد يتلقى أمرًا جديدًا متعلقًا **بالتاب النشط نفسه**.

**Lovable يعرض الواجهة فقط.** لا يمتلك حق الوصول إلى متصفح الكمبيوتر
المحلي ولا يستطيع عرض مواقع حساباتك الحقيقية في الاستضافة السحابية.
لهذا السبب تظهر قوائم فارغة وحالة «غير متصل» هناك: **لا توجد بيانات
تجريبية مخفية أو نتائج مختلقة**. يبقى التشغيل الفعلي على جهازك.

## قائمة حالة قصيرة وصريحة

| الوظيفة | الموجود في الكود | التحقق العملي |
|---|---|---|
| الصفحة الرئيسية = المتصفح وصندوق التعليمات | نعم | بناء واختبار عرض Chromium |
| فتح/تغيير/إغلاق التبويبات والتصفح اليدوي | نعم؛ يعمل عبر العامل المحلي | اجتاز اختبارات CI، لم يُجرّب على Windows الخاص بك |
| حفظ جلسة Chromium في Docker Volume | نعم | اختبار حفظ كوكي اختبارية واستعادتها في حاويات GitHub |
| عرض نافذة Chromium بـ noVNC | نعم | اختبار Docker مؤقت، يحتاج اختبار Windows |
| نموذج Ollama المحلي وتوليد ملخص صفحة | موجود | اختبارات ببروتوكول Ollama تجريبي؛ نموذج حقيقي غير مختبر على جهازك |
| أوامر المساعد في نفس التاب: تمرير، رابط آمن بنفس الموقع، ملء نص/بحث | كود وتنفيذ Playwright حقيقي | **نجح** اختبار Chromium على صفحة اصطناعية معزولة، لا على مواقع حسابات فعلية |
| منع تبديل التاب/الموقع أثناء المهمة | موجود في عامل المتصفح | فحوص سياسة واختبارات وحدة؛ يلزم تجربة محلية متكاملة |
| إلغاء المهمة والتوقف الطارئ | موجود | اختبارات آلية؛ يلزم اختبار فعلي |
| الضغط الحر على أي زر وإرسال نموذج | **غير مدعوم** | ليس جاهزًا |
| إرسال واتساب أو بريد أو تعليق، شراء/دفع/حذف | **غير مدعوم** | لا يوجد منفذ تنفيذ خارجي |
| أداء مهمة طويلة بشكل مستقل على مواقع متعددة | **غير مدعوم** | حد أقصى أربع خطوات آمنة في المهمة الواحدة |
| لوحة تشخيص الخدمات من الإعدادات | موجودة: PostgreSQL وFastify وChromium وnoVNC وOllama، وعدد النماذج وتفويض الجلسة | نجحت اختبارات المنطق والواجهة على GitHub؛ لم تُختبر على Windows الخاص بك |
| تشغيل كل شيء على Windows مع نموذج Ollama حقيقي | سكربتات إعداد وتشغيل موجودة | **لم يتم الاختبار على جهاز المستخدم بعد** |

### تحسين دقة نتائج الوكيل — 19 أكتوبر 2026

- إذا اختار النموذج إنهاء مهمة تصفح دون تنفيذ أي خطوة موثقة، تسجّل
  النتيجة بوضوح «لم ينفذ المساعد أي إجراء» ولا تُنقل ادعاءات النموذج
  عن إرسال أو نشر لم يحدث.
- ما زالت المهام العملية مقيدة بنفس التبويب والنطاق، وبحد أقصى أربع خطوات
  متاحة فقط؛ إكمال المهمة في قاعدة البيانات لا يعني إتمام إجراء خارجي.
- أُضيف اختبار انحدار للتأكد من عدم تمرير ادعاء «تم إرسال الرسالة»
  عندما يكون سجل عمليات المتصفح خاليًا.
- التشغيل الحقيقي على Windows مع نموذج Ollama فعلي ما زال بحاجة تجربة.

## حدود تنفيذ المساعد

1. يمكنك فتح أي موقع HTTP/HTTPS داخل Chromium **يدويًا**. تنفيذ
   المساعد مقيد حاليًا بموقع **HTTPS عام** وبنفس **التاب والنطاق بالضبط**
   اللذين اخترتهما، ولا يصل إلى شبكات داخلية أو نطاقات أخرى.
2. التصفح الآلي الحالي مقيد بأربع خطوات في الأمر الواحد، مع مراجعة
   فعلية للصفحة عند كل خطوة. النموذج يقترح JSON محدودًا، والعامل
   يتحقق منه قبل التنفيذ. لا تُفسّر رسالة النموذج وحدها كدليل تنفيذ.
3. ملء حقل نصي **لا يضغط إرسال**، لكن بعض المواقع تحفظ المدخلات
   تلقائيًا عند الكتابة؛ لا تستخدم المهمة الآلية لإدخال كلمات مرور
   أو معلومات حساسة أو إجراء تغييرات لا تريد تسجيلها في الموقع.
4. لا يتم تشغيل وكيل حقيقي في Lovable: أي نجاح للاختبارات السحابية
   يعني أن الكود والمسارات قيد الاختبار صحيحة، لا أن دخولك إلى
   الحسابات أو نجاح المهام على جهازك قد تم إثباتهما.

## استخدام النسخة المحلية لاحقًا بأقل خطوات

عند تجهيز Windows ستحتاج Docker Desktop وNode.js وBun وOllama.
بعد تثبيتهم لأول مرة، من جذر مجلد المشروع:

```powershell
.\scripts\windows\launch.ps1
```

هذا الأمر يجهز ملفات الإعداد عند غيابها بالكامل، ثم يشغّل المتصفح
وPostgreSQL والواجهة. لن يحذف إعدادًا أو يُعيد كتابة أسرارك لو وجد
تكوينًا سابقًا. يلزم تثبيت نموذج Ollama محليًا بشكل منفصل
(مثال: `ollama pull llama3.2`) وإدخال رمز الخادم داخل **الواجهة
المحلية فقط**. قد يطلب noVNC كلمة مرور مستقلة من ملف
`browser-worker/.env`. هذه الخطوات لم تُختبر بعد على جهازك.
