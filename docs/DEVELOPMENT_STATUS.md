# تقرير تقدم Personal AI Workspace
**آخر تحديث: 2026-10-17** · المستودع: `Ahmedmadni/pixel-perfect-clone` · الفرع: `main`.

## الحالة المعتمدة بعد حذف البيانات التجريبية

**اقرأ أولًا [حالة المتصفح المختصرة](CURRENT_STATUS.md)** بدل اعتبار
أعداد الاختبارات أو لقطات Lovable دليلًا على تشغيل مواقعك الحقيقية.

- أصبحت الصفحة الرئيسية `/browser` شاشة واحدة تحتوي متصفح Chromium
  والتبويبات الموجودة وصندوق تعليمات Ollama لنفس التاب.
- تم حذف كل سجلات وتبويبات وحسابات وموافقات ومهام ورسائل
  المعاينة الافتراضية، وتعطيل كتابة معلومات وهمية في المتصفح.
- أُضيفت خطوات محلية مقيدة: قراءة/تلخيص، تمرير، فتح رابط HTTPS آمن
  في **نفس الموقع والتبويب**، والكتابة في حقول غير حساسة **دون إرسال**.
- يسمح المتصفح يدويًا بفتح أي موقع HTTP/HTTPS؛ لكن وكيل AI مقيد
  بالموقع العام HTTPS الأصلي للتبويب النشط حتى لا يغير حسابًا آخر.
- لا يوجد إرسال رسائل أو دفع أو حذف أو نقر حر أو تنفيذ مفتوح للمواقع.
- هناك حد أربع خطوات آمنة لكل مهمة؛ لا تدّع اكتمال أي مهمة إذا لم
  يُنفذ العامل خطوة فعلية ويؤكدها.
- اختبار Chromium على صفحة اصطناعية معزولة مثبت في GitHub CI.
  لا تزال تجربة Windows الشخصية مع Ollama حقيقي **غير منفذة**.
- `scripts/windows/launch.ps1` يوفر أمر التشغيل الموحد مع عدم
  استبدال ملفات الأسرار الموجودة.

**ملاحظة:** الأقسام أدناه سجل تاريخي لتطور المشروع وقد تتحدث عن
واجهات ومراحل تجريبية تم استبدالها؛ الوضع الحالي الدقيق هو المذكور
أعلاه وفي `CURRENT_STATUS.md`.

عن التشغيل الحقيقي: اختبار CI في وضع عدم الاتصال مع استثناء مقيّد،
أما Chromium الحقيقي للمستخدم فيبقى `chromiumSandbox:true`.

### المراحل المنفذة في الكود

- **المرحلة 1 — الواجهة:** لوحة تحكم RTL، صفحات المتصفح والمحادثة والموافقات
  والصلاحيات والذاكرة والإشعارات، ووسم واضح للبيانات التجريبية.
- **المرحلة 2A — الأساس المحلي:** Fastify، تفويض Bearer، CORS مقيّد،
  محرك حالات التحكم وسجل تدقيق في PostgreSQL.
- **المرحلة 2B — المحادثة:** اكتشاف نماذج Ollama المثبتة محليًا، ردود تدريجية
  وإلغاء التوليد وتاريخ محادثة دائم.
- **المرحلة 2C — المتصفح:** Chromium/Playwright في نافذة حقيقية عبر
  Xvfb + noVNC، تبويبات فعلية وملف جلسة مستمر في Docker Volume، ويدوي/توقف.
- **المرحلة 2D — الذاكرة:** CRUD وإصدارات واستعادة سابقة، مع إدراج تعليمات
  وأنماط رد مختارة من الذاكرة في سياق المحادثة المحلية.
- **المرحلة 2E — المراجعة المقيدة:** مهمة واحدة عند طلب المستخدم لقراءة
  تبويب HTTPS مصرح به، وصياغة تقرير عربي؛ إلغاء المهام ومنع التنفيذ الخارجي،
  وقرارات موافقة لمسودات غير قابلة للتنفيذ.
- **المرحلة 2F — إشعارات داخل التطبيق:** حالات إكمال وفشل وإلغاء المهمات
  محفوظة في PostgreSQL بلا نسخ محتوى الصفحة.

### نتائج فحص استعادة جلسة Chromium — 2026-10-16

- كشف اختبار إعادة تشغيل الحاوية أن Xvfb كان يحتفظ بقفل شاشة قديم في
  `/tmp`، مما يمنع إعادة التشغيل حتى لو كانت ملفات Chromium محفوظة.
- تم تجهيز مجلد مقبس X11 بالتصاريح الصحيحة وتنظيف **أقفال العرض القديم فقط**
  عند بداية الحاوية، بشرط عدم وجود خادم X حي.
- نجح اختبار سحابي حقيقي: إضافة كوكي تجريبية طويلة الأجل إلى ملف
  Chromium، إعادة تشغيل Docker، واستعادة الكوكي من نفس ملف الجلسة.
- تحقّق الاختبار أيضًا من عودة الملكية إلى `STOPPED` ووضع
  `viewOnly`، مع استمرار تشغيل noVNC. رقم التشغيل:
  https://github.com/Ahmedmadni/pixel-perfect-clone/actions/runs/38882219290
- وضع الاختبار السحابي **غير متصل بالخارج** ولا يستخدم حسابات المستخدم،
  مع استثناء خاص لبيئة GitHub فقط. لا يُسمح بهذا الاستثناء في Windows الحقيقي.
- تمت إضافة `scripts/windows/diagnose.ps1` لفحص الخدمات دون إظهار رموز،
  وخيار `-TestInference` للتحقق من رد Ollama حقيقي محليًا (غير مُختبر
  بعد على جهاز المستخدم). يفحص GitHub صياغة السكربت ولا يشغله على Windows.

## حماية إعادة تشغيل خادم Fastify

- يمنع فحص `runtime/src/startup-safety.ts` انتقال ملكية جلسة قديمة
  إلى الخادم الجديد. عند بدء الخادم، يتم أولًا استعادة حالة PostgreSQL
  بصورة آمنة، ثم إرسال أمر `STOPPED` للمتصفح عند الحاجة والتحقق أن
  إدخال VNC مقفل (`viewOnly`).
- إذا تعذر التأكد من توقف المتصفح، تبقى API المتصفح **معطلة لذلك التشغيل**
  ويظل بإمكان المستخدم الوصول إلى المحادثة والذاكرة المحلية.
- توجد اختبارات مستقلة لحالات البدء من `MANUAL` و`AGENT_ACTIVE`
  و`PAUSED`، وتعذر اتصال العامل، وفشل قفل الإدخال.
- لم تُجرَ حتى الآن إعادة تشغيل مشتركة على جهاز Windows الفعلي؛
  الاختبار المتكامل على GitHub يستخدم حاويات مؤقتة.

## استعادة PostgreSQL المشفّرة — فحص حقيقي على GitHub

- تم تنفيذ `scripts/backup/crypto.mjs` بتشفير AES‑256‑GCM
  ومفتاح مشتق من عبارة مرور باستخدام scrypt مع ملح وIV عشوائيين.
- ينشئ `scripts/backup/db-backup.mjs` أرشيف `pg_dump -Fc` مشفرًا
  أثناء التصدير، من دون كتابة نسخة غير مشفرة للبيانات أثناء النسخ.
- يدعم وضع `verify` فحص الملف المشفر بالكامل دون استعادة أو كتابة
  نسخة نصية على القرص؛ وتتم إعادة فحص التشفير عند الإنشاء قبل اعتماد
  النسخة النهائية.
- لا تدخل كلمة المرور في معاملات سطر الأوامر أو في GitHub؛
  توفر `scripts/windows/backup.ps1` و`restore.ps1` إدخالًا محليًا.
- الاستعادة تتحقق من صحة الأرشيف المشفر بالكامل قبل إنشاء **قاعدة جديدة**
  باسم `paw_restore_...`، ولا تستبدل بيانات `paw`.
- أنشئت اختبارات لفشل كلمة المرور، وعبث البيانات، وعدم إنتاج ملف
  غير مشفر عند فشل المصادقة، ولنسخ قاعدة PostgreSQL حقيقية مع
  بيانات اختبارية واسترجاعها ومقارنتها ببيانات المصدر.
- نجحت مهمة CI المخصصة للنسخ المشفر ضمن
  https://github.com/Ahmedmadni/pixel-perfect-clone/actions/runs/38883955794
- يتكون ملف PostgreSQL غير مشفر مؤقتًا خلال عملية الاستعادة فقط،
  ثم يتم حذفه؛ للحفاظ على الخصوصية عند استخدام أقراص SSD يجب
  تفعيل تشفير القرص الكامل. لم تُختبر العملية على Windows الخاص بالمستخدم.
- لا تشمل النسخ الحالية ملفات جلسات Chromium أو ملفات إعداد
  الخدمات، ولا توجد بعد جدولة تلقائية آمنة لكلمة مرور النسخة.

الدليل: [BACKUP_AND_RESTORE.md](BACKUP_AND_RESTORE.md).

## جدولة نسخ PostgreSQL المشفرة على Windows (اختيارية)

- `scripts/windows/scheduled-backup.ps1` يتيح التفعيل اليدوي لنسخة يومية،
  فحص الحالة، تشغيل نسخة يدويًا، وإلغاء الجدولة دون مسح النسخ السابقة.
- يستخدم Windows Task Scheduler لحساب المستخدم المسجّل فقط، مع
  كلمة مرور استعادة مخزنة باستخدام Windows DPAPI CurrentUser
  وملفات إعداد مقيدة الوصول ضمن `%LOCALAPPDATA%`.
- لا توضع العبارة السرية ضمن معاملات المهمة المجدولة أو ضمن
  GitHub/Lovable، ولا توجد جدولة افتراضية أو حذف تلقائي للأرشيفات.
- نجح اختبار Windows سحابي لعملية DPAPI ذاتها؛ **إنشاء مهمة Task Scheduler
  حقيقية وتشغيلها على جهاز المالك لا يزال يحتاج التحقق المحلي**.
- عبارة استعادة النسخة يجب حفظها خارج جهاز المستخدم، لأن DPAPI
  لا يتيح نقل الأسرار المحمية تلقائيًا إلى جهاز جديد.

## نسخ Chromium المشفّر والمنفصل

- تمت إضافة `scripts/backup/browser-profile.mjs` لحفظ ملف جلسات Chromium
  في أرشيف مشفّر مستقل `.pawprofile` مع بصمة AES‑GCM خاصة تمنع استخدامه
  كنسخة PostgreSQL.
- يرفض النسخ إذا كان متصفح Chromium أو أي حاوية أخرى تستخدم Docker Volume؛
  يجب إيقاف حاوية `browser-worker` يدويًا قبل النسخ.
- تُقرأ ملفات Docker Volume في حاوية مؤقتة بمصدر للقراءة فقط
  ومن دون شبكة، مع قدرة `DAC_OVERRIDE` محدودة للوصول إلى الملفات
  ذات الملكية المختلطة. لا توجد أي حاوية متصفح تعمل وقت النسخ.
- الاستعادة تُنشئ حجم تخزين جديدًا غير متصل بالمتصفح، ولا تبدّل كوكيز
  جلسة المستخدم أو تمس ملف Chromium الأصلي.
- أرشيف الاستعادة يفك التشفير في ملف مؤقت قبل الاستيراد، ولذلك يتطلب
  تشفير القرص الكامل في Windows. لا يضمن استمرار تسجيل الدخول بين
  الأجهزة لأن بعض الكوكيز قد تكون مرتبطة ببيئة Chromium المحلية.
- **نجح اختبار GitHub الحقيقي** مع كوكي اختبارية غير شخصية:
  رفض الأرشفة أثناء تشغيل Chromium، وأنشأ نسخة مشفّرة بعد توقفه،
  وتحقق من سلامتها، ورفض كلمة مرور خاطئة، ثم استعادها داخل Docker
  Volume منفصل غير مربوط بالتطبيق.
  [نتيجة الاختبار](https://github.com/Ahmedmadni/pixel-perfect-clone/actions/runs/38887246668).
- لم تُختبر بعد على Windows الشخصي أو بجلسة دخول حقيقية؛ لا توجد
  ضمانات لنقل جلسة مصادقة بين الأجهزة.

دليل الأمان: [CHROMIUM_PROFILE_BACKUPS.md](CHROMIUM_PROFILE_BACKUPS.md).

  `POST /v1/approvals` من وضع Mock على الهاتف والكمبيوتر.

## المتبقي الضروري

1. **التحقق على Windows/WSL2**: توافق Docker/Chromium Sandbox، واجهة noVNC،
   إدخال لوحة المفاتيح والماوس، وحفظ تسجيلات الدخول بعد إعادة تشغيل المتصفح.
2. **تشغيل Ollama الحقيقي** محليًا بنموذج مثبت واختبار العربي والبث والإلغاء
   وحالات انقطاع الخدمة.
3. تجربة النسخ المشفّر والاستعادة على Windows عمليًا، ثم وضع سياسة نسخ دورية آمنة، مع إبقاء ملفات المتصفح والأسرار منفصلة.
4. تطوير تنفيذ مهام أوسع **فقط بموافقة صريحة** وبواجهات منصات رسمية
   مصرح بها، بعد التحقق من سلامة قواعد التفويض.
5. مواصلة اختبارات CI وعدم إظهار الخدمات على أنها جاهزة إذا لم تتصل فعليًا.

## مبادئ العمل

- محلي أولًا؛ لا يلزم مزود ذكاء اصطناعي مدفوع أو متصفح مستضاف.
- الأسرار والملفات الشخصية لا ترفع إلى المستودع العام.
- **كل الصلاحيات الخارجية مغلقة افتراضيًا.**
- «اعتماد مسودة» لا يعني إرسالها أو تنفيذها تلقائيًا.
- اختبار CI ناجح لا يساوي جاهزية إنتاجية على جهاز المستخدم.
